# DarkHarold2 — Codebase Map

DarkHarold2 is a browser-based recreation of Fallout 2, forked from the DarkFO
project (Apache 2.0). Written in TypeScript (no implicit any / returns; `strictNullChecks`
off) with WebGL 2.0 rendering and a Python 3 asset pipeline. Estimated completion: ~99%
(canonical figure: ROADMAP.md).

Ground-truth reference: [fallout2-ce](https://github.com/alexbatalov/fallout2-ce)
(authoritative C++ source). Secondary: [jsFO](https://github.com/ajxs/jsFO).

---

├── tools/           Asset pipeline (Python 3) — moved here from repo root 2026-06-18

│   ├── pipeline_gui.py    Tkinter GUI front-end for setup.py
│   ├── fomap.py           Map extractor (MAP → maps/*.json)
│   ├── exportImagesPar.py FRM → PNG sprite exporter (parallel; the one setup.py actually uses)
│   ├── exportImages.py    Non-parallel FRM → PNG variant (documented but not setup.py-wired)
│   ├── exportPRO.py       PRO → proto/**/*.json extractor
│   ├── frmpixels.py       FRM pixel helpers (used by exporters)
│   ├── pal.py             PAL palette loading
│   ├── proto.py           PRO binary parser
│   ├── dat2.py            DAT2 archive extractor
│   ├── fonts.py           FON font extraction
│   ├── convertAudio.py    ACM → WAV (acmDecoder.py: CE sound_decoder.cc port, no ffmpeg)
│   ├── stitchWorldmap.py  World map tiles → art/worldmap.png (stitch_worldmap stage)
│   ├── convertLST.py      LST → JSON pre-bake (lut/lst/)
│   ├── convertPRO.py      Standalone PRO converter (debug)
│   ├── convertEndgame.py  Endgame slide extraction
│   └── parseCritTable.py  Extracts criticalTables.json from fallout2.exe

├── tsconfig.json    TypeScript config (target: ES2021, outDir: js/, noImplicitAny; strictNullChecks off; source maps)
├── package.json     npm devDeps only: typescript, eslint, playwright (npm run parity); scripts build / lint:ratchet / test / parity
├── test/            Unit tests (node --test on js/, npm test): formula code vs fallout2-ce; support/ stubs logger + globalState
├── .github/workflows/ci.yml  CI on push / PR: tsc, ESLint ratchet (tools/eslintBaseline.json), npm test
├── Pipfile          Python deps for asset pipeline
├── CLAUDE.md        Claude Code project instructions
├── ROADMAP.md       Phased roadmap to 95% completion
├── docs/            README images (screenshot.png); the old planning .docx files are text in wiki/planning_archive.md

the pipeline or the TS compiler.

### Scripting VM

Three-file split — understand this before touching any opcode:

| File | Purpose | fallout2-ce counterpart |
|------|---------|------------------------|
| `src/vm.ts` | `ScriptVM` class + `opMap`: low-level bytecode decoder (stack ops, arithmetic, jumps, 319 lines) | `scripts.cc` (VM core) |
| `src/vm_bridge.ts` | `bridgeOpMap`: maps ~118 bytecode opcode values to `Script` methods via `bridged(procName, argc)` factory (245 lines) | `scripts.cc` (opcode table) |
| `src/scriptProcs.ts` | SCRIPT_PROC_* numbers (`script_action`) and the intrinsics that end a procedure on its own `self_obj`, shared by both script backends | `scripts.cc gScriptProcNames`, `interpreter_extra.cc` |
| `src/scripting.ts` | `Script` class: one method per FO2 script intrinsic, TimedEvent system, GVAR/LVAR/MVAR access, all hook entry points (~2263 lines) | `scripts.cc`, `script_list.cc` |
| `src/sfallArrays.ts` | sfall arrays (list / associative, temporary arrays freed per game tick) for the Unofficial Patch's scripts ([wiki/upu_support.md](wiki/upu_support.md)) | `sfall_arrays.cc`, `sfall_lists.cc` |
| `src/sfallIni.ts` | `get_ini_setting` / `set_ini_setting`: reads `file\|section\|key` from the install's ini files the pipeline copied (`data/ddraw.ini`, a mod's `data/mods/<mod>.ini`) | `sfall_ini.cc` |
| `src/sfallGlobalScripts.ts` | sfall global scripts (the active mods' `gl*.int`: start, repeat, type, map procedures, `game_loaded`) and sfall global variables (saved) | `sfall_global_scripts.cc`, `sfall_global_vars.cc` |
| `src/sfallHooks.ts` | sfall hook scripts (`register_hook_proc`, `get_sfall_arg`, `set_sfall_return`; `HOOK_INVENTORYMOVE`, `HOOK_GAMEMODECHANGE`) and `get_game_mode` flags | — (DH2 addition after sfall `HookScripts.cpp`) |
| `src/sfallFs.ts` | sfall's virtual files (`fs_copy`, `fs_seek`, `fs_read_*`, `fs_write_*`); an art FRM header edits the image's fps | — (DH2 addition after sfall `FileSystem.cpp`) |
| `src/modAssets.ts` | Mod asset overlay: `assetUrl(path)` picks the highest-priority active mod folder (`mods/<name>/manifest.json`) that has a file; merges `art/imageMap.json` / `proto/pro.json`; rewrites overridden `ui.css` images | — (DH2 addition after sfall's `mods_order.txt`) |
| `src/transpiler.ts` | INT file disassembler / transpiler (produces debug output) | — |
| `src/intfile.ts` | `.INT` binary parser: procedure table, code section, string pool | — |
| `src/lua/luaRuntime.ts` | Lua script backend: starts wasmoon (`lib/wasmoon/`), `attachLuaScript` gives a `Script` one method per Lua procedure; `[dh2] script_backend=lua` ([wiki/lua_scripts.md](wiki/lua_scripts.md)) | — (DH2 addition) |
| `src/lua/prelude.ts` | Lua side: SSL semantics (`div`, `mod`, string `+`, `AND`/`OR`), per-script sandbox, coroutines for `gsay_end`/`gsay_message` | `interpreter.cc opAdd/opDivide/opModulo`; `game_dialog.cc gameDialogEnter` |
| `src/lua/luaDiff.ts` | VM-vs-Lua differential test behind `tools/luadiff.html` | — |

To add an opcode: implement a method on `Script` in `scripting.ts`, then wire
it in `vm_bridge.ts` with `bridged("methodName", argCount)`; the Lua backend calls
`Script` methods by name, and `tools/int2lua.py` needs the opcode in its
`INTRINSICS` table (`--check-bridge src/vm_bridge.ts` compares the two).

## Asset Pipeline

Run `pipenv run python tools/setup.py /path/to/Fallout2/` once to extract all assets.
The engine consumes only pre-baked JSON/PNG — no runtime DAT parsing.

| Stage | Script | Output |
|-------|--------|--------|
| DAT extraction | `tools/dat2.py` | raw files |
| FRM → PNG | `tools/exportImagesPar.py` / `exportImagesPar_updated.py` | `art/**/*.png` |
| PRO → JSON | `tools/exportPRO.py` | `proto/**/*.json` |
| MAP → JSON | `tools/fomap.py` | `maps/*.json`, `maps/*.images.json` |
| LST → JSON | `tools/convertLST.py` | `lut/lst/*.json` |
| PRO indexes | `tools/convertPRO.py` (no pipeline stage; nothing reads its output) | `lut/pro/*.json` (proto lookup) |
| AAF/FON fonts | `tools/fonts.py` | `art/fonts/` |
| ACM → WAV | `tools/convertAudio.py` (`export_audio` stage, default; `tools/acmDecoder.py`, a port of CE `sound_decoder.cc`) | `audio/**/*.wav` |
| AAF/FON fonts → PNG atlas + web font | `tools/exportFonts.py` (`export_fonts` stage; the `.woff` needs fontTools) | `art/fonts/font<N>_aaf.png/.json/.woff`, `font<N>_fon.png/.json` |
| MVE → WebM | `tools/convertMovies.py` (`export_movies` stage; needs ffmpeg) | `art/cuts/*.webm` + `.json` |
| Speech ACM → MP3 | `tools/convertSpeech.py` (`export_speech` stage; needs ffmpeg) | `audio/speech/<head>/*.mp3` |
| Crit table | `tools/parseCritTable.py` | `lut/criticalTables.json` |

All of these are converted from the user's own Fallout 2 install and never committed (`.gitignore`;
untracked 2026-10-22: the fonts, `lut/lst/`, `lut/pro/`, `lut/criticalTables.json`, `lut/elevators.json`;
2026-10-23: `art/imageMap.json`).
A fresh clone needs the pipeline run before the game starts.
| GAM → JSON | `tools/parse_gam.py` (`convert_gam` stage; CE `globalVarsRead`) | `data/gvars.json` (from `data/data/vault13.gam`), `data/maps/*.mvars.json` |
| INT → Lua | `tools/int2lua.py` (`decompile_scripts` stage; own decompiler, [wiki/lua_scripts.md](wiki/lua_scripts.md)) | `data/scripts/*.lua` (git-ignored, next to the `.int`) |
| Default config | `tools/fallout2Cfg.py` (`write_config` stage; never overwrites) | `fallout2.cfg` (git-ignored) |
| Worldmap stitch | `tools/stitchWorldmap.py` (`stitch_worldmap` stage, after `export_images`) | `art/worldmap.png` |
| Color tables | `tools/pal.py` (via pipeline) | `lut/colorTable.json`, `lut/color_lut.json`, `lut/color_rgb.json` |

Key conventions:
- Tile coordinate: `tileNum = y * 200 + x` (200-wide grid, max 40 000 tiles/elevation)
- PID high byte type: 0=items, 1=critters, 2=scenery, 3=walls, 4=tiles, 5=misc
- LST naming: `art/critters/critters.lst` → `lut/lst/art_critters.json`

## Scripting VM — Opcode Coverage

_Last audited: 2026-10-06 against `main` branch (opcode table re-verified; first pass 2026-05-31)._

`vm_bridge.ts` wires **~130 opcodes** via the `bridged()` factory plus a few custom
inline handlers (including `gsay_end` and `giq_option`).

sub-IDs now log via `dbgWarn`. Remaining no-op paths: `play_gmovie` (S15),
`obj_can_hear_obj` (S28), metarule 52/53 (car cargo, W8).

**Note on `giq_option` and `gsay_end`:** both are wired — they have custom
inline handlers in `vm_bridge.ts` (lines 191 and 203) rather than using
`bridged()`. The `//,0x811D: bridged("gsay_end", 0)` and
`//,0x8121: bridged("giq_option", 5)` comments above them are leftover
reminders of the original bridged form, not the live wiring.
